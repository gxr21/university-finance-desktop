# المرحلة الأولى: تحليل وتصميم نظام الإدارة المالية والإدارية الجامعية

**اسم النظام:** نظام الإدارة المالية والإدارية الجامعية (UFAM)  
**النطاق:** كلية داخل جامعة، مع هوية مؤسسية تُدار من الإعدادات وليس من الشيفرة.  
**المبدأ الحاكم:** فصل الصلاحيات (SoD) بين الإدارة الأكاديمية والمالية، ودفتر حركات غير قابل للحذف الصامت.

هذا المستند يثبّت القرارات التي بُني عليها التنفيذ. لا تُفترض نسب خصم وزارية أو معادلات أجور تدريسيين غير مُدخلة من الإدارة.

---

## 1. المتطلبات غير المحددة والقرارات المعتمدة

| الموضوع | القرار |
| --- | --- |
| نسب الخصم وقيم الأقساط | تُخزَّن في قواعد قابلة للتهيئة. البذرة التجريبية للعرض فقط، وواضحة في السجلات. |
| الجمع بين الخصومات | قاعدة لكل نوع: `stackable`. سقف عام في الإعدادات `max_discount_rate` و`max_discount_amount`. الناتج لا ينزل عن صفر. |
| تطبيق سياسة قسط جديدة | عند التعديل يُسأل: طلبة جدد فقط، أو إعادة إصدار فواتير بلا وصولات. الفواتير التي لها وصولات لا تُعاد كتابتها. |
| الدفع الزائد | مغلق افتراضياً (`allow_overpayment=0`). |
| موافقة التسجيل | مفعّلة افتراضياً. الحساب الجديد `pending` بلا أدوار مالية. |
| صلاحيات مدير النظام | إدارية فقط. أرصدة الخزائن والتقارير المالية تتطلب منحاً صريحة. |
| أجور التدريسيين | وحدة مستقلة عن خزنتي الطلبة. لا تُخلط مع إيراد الأقساط إلا بقيد تسوية موثّق لاحقاً. |
| استعادة كلمة المرور | رمز عشوائي محدود العمر، يُخزَّن هاشه فقط. في التطوير يُكتب رابط الاستعادة في سجل محلي بلا كلمة المرور. |
| التحقق العام من الوصل | صفحة عامة تعرض صحة الوصل والرقم والتاريخ واسم الطالب دون المتبقي أو تفصيل الذمة. |
| تزامن الصرف | `SELECT … FOR UPDATE` على الخزنة والفاتورة داخل معاملة واحدة. |
| العملة | دينار عراقي (`IQD`) قابل للتغيير من الإعدادات. |
| QR | حمولة عشوائية غامضة، بلا كلمة مرور أو قائمة صلاحيات. لا يوسّع صلاحيات الحساب. |

## 2. الأدوار والصلاحيات

الصلاحية تُفرض في الخادم على كل طلب. إخفاء الزر واجهة فقط.

### 2.1 الأدوار الأساسية

| الرمز | الاسم | النطاق |
| --- | --- | --- |
| `system_admin` | مدير النظام | المستخدمون، الأدوار، الهوية، الهيكل الأكاديمي، QR، النسخ الاحتياطي، سجل التدقيق. بلا أرصدة ما لم تُمنح. |
| `finance_manager` | مدير الحسابات | الأقساط، الخصومات، الفواتير، الخزائن، التقارير المالية، مراجعة المصروفات. |
| `cashier` | أمين الصندوق | البحث عن الطالب، تسجيل دفعة، إصدار وصل، طباعة A5، الاطلاع على الخزنتين وفق المنح. |
| `expense_accountant` | محاسب المصروفات | مسودات كتب الصرف وبنودها. **ممنوع** رصيد الخزنة والتقارير الإيرادية. |
| `student_affairs` | شؤون الطلبة | ملفات الطلبة، الأرشيف، الوثائق. بلا إصدار وصل أو تعديل قسط. |
| `student` | الطالب | بياناته ووصولاته وإشعاراته فقط. |
| `auditor` | المدقق | قراءة مالية وسجل تدقيق بلا قبض أو صرف. |

يمكن إسناد أكثر من دور، مع صلاحيات فردية إضافية أو حجب (`user_permissions.effect = allow|deny`).

### 2.2 كتالوج الصلاحيات

## 3. تدفق العمليات المالية

```
تسجيل طالب → قيد دراسي (سنة + نوع + مرحلة + قسم)
        → إصدار فاتورة من سياسة القسط (لقطة مبلغ)
        → اعتماد خصم (لقطة قاعدة)
        → إعادة احتساب الصافي على الخادم
        → قبض أمين الصندوق (معاملة واحدة)
              ├─ دفعة posted
              ├─ وصل فريد + أرشفة
              └─ حركة دائنة في خزنة نوع الدراسة
```

```
كتاب مصروف مسودة → تقديم → موافقة → صرف
                              └─ حركة مدينة من الخزنة المختارة
                                 (رفض عام إن لم يكفِ الرصيد)
```

التصحيح: حركة عكسية مرتبطة بالأصل، مع السبب والمنفّذ. الأصل يبقى.

## 6. قرارات تقنية

- PHP 8.3 + MySQL 8 + PDO وPrepared Statements.  
- الواجهة HTML/CSS/JS وFetch، بدون React/Vue.  
- الجلسة في جدول `user_sessions` لإبطالها عند التعطيل.  
- المبالغ `DECIMAL(18,2)` والحساب عبر BCMath.  
- الرصيد = مجموع الحركات المرحلة، ليس حقلاً يُعدَّل يدوياً.  
- الملفات الحساسة خارج `public/` وتُنزَّل عبر مسار محمي.  
- كلمة مرور الإدارة الابتدائية من المتغير `ADMIN_INITIAL_PASSWORD` فقط.
